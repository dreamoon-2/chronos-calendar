# 0.5.0 功能体验与测试指南

0.5.0 统一了网页、Windows 与 Android 的界面与交互：移除日程草稿、保留并适配待办清单、去掉左右箭头、重做标题栏与视图标签、缩窄时间列，并新增移动端滑动切视图与「日程」列表。正式安装包见 [v0.5.0 Release](https://github.com/dreamoon-2/chronos-calendar/releases/tag/v0.5.0)；也可按下方路径使用本机构建产物。

## 一、打开正确的版本

**Windows 日常使用**：从系统托盘退出旧版 Chronos，运行 `src-tauri/target/release/bundle/nsis/Chronos Calendar_0.5.0_x64-setup.exe` 安装，再启动。界面右侧「更多操作」菜单底部应显示 `Chronos v0.5.0`。系统通知和开机启动使用安装版测试；直接运行构建目录中的 exe 适合查看界面。

**Android 手机体验**：安装本次生成的 `release/Chronos-Calendar_0.5.0_android.apk`，系统版本为 0.5.0（versionCode 6）。沿用本项目原有签名，可覆盖安装原 release 版。桌面开机启动与 Windows 通知入口只在 Windows 版提供。

**云端账号升级**：已有 0.3.x 数据库需先执行 `supabase/migrations/202610190001_tasks.sql` 和 `202610200001_task_event_link.sql`，待办才能跨端同步并支持拖回；已执行过待办迁移的 0.4.0 数据库只需补执行后者。未执行时日程功能不受影响，待办面板会提示「待办表尚未创建」，执行迁移后点「重试」即可。

**网页开发体验**：在 PowerShell 进入项目根目录，再启动开发服务器：

```powershell
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
npm run dev
```

保持终端运行，打开输出中的地址，默认 `http://localhost:1420`。只想验证演示模式、又不希望连接 `.env.local` 里的真实账号时，使用：

```powershell
npm run dev:demo
# 或指定端口
npm run dev:demo -- --port 5173
```

- `ENOENT ... package.json`：终端没有位于项目根目录，先运行上面的 `Set-Location`。
- `Port 1420 is already in use`：先打开 `http://localhost:1420`；已有服务器可能正在运行。需要独立网页预览时可运行 `npm run dev -- --port 5173`，并打开 `http://localhost:5173`。
- 启动新 exe 后仍显示旧版本：托盘里可能还有旧进程，Tauri 单实例会聚焦旧窗口。从托盘菜单「退出」旧程序后重新启动新 exe，版本号应更新。
- Tauri 桌面开发固定使用 1420，需要先在占用该端口的开发终端按 Ctrl+C，再运行 `npm run desktop:dev`。
- 源码与已经打包的 exe／APK 分开更新。开发网页更新不会改变旧安装包。

## 二、手工体验清单

建议先用测试日程，避免误改自己的正式安排。

| 功能 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 新标题栏 | 打开日历 | 左侧日历图标 + 大号「2026/10」；右上角为今天、待办、更多三个图标（待办图标带未完成数量角标）；下方为年／月／周／日／日程五段文字标签，当前视图下方有蓝色短横线 |
| 日期选择 | 点标题或左侧日历图标；在浮层中翻月、点某天 | 浮层出现迷你月历；翻月只改变浮层，点日期后主视图跳到该日期并关闭浮层 |
| 无左右箭头 | 查看标题右侧 | 只有今天／待办／更多图标，没有 `‹`、`›` 或「上一段／下一段」；桌面用 `← / →` 翻页、`T` 回到今天 |
| 移动端滑动 | 在手机上从右向左滑，再从左向右滑 | 依次切换年→月→周→日→日程；反向返回；纵向滚动、双指缩放、按住日程拖动不会误切视图，也不误开表单 |
| 日程视图 | 点「日程」 | 按周分组列出日程：星期、日期、农历／节气、时间与标题；无日程时显示「这一周还没有安排」 |
| 窄时间列 | 周／日视图查看左侧时间列 | 只显示 `0`–`23` 数字，不显示 `00:00`；列宽明显变窄，日程卡片可显示更多文字 |
| 农历与节气 | 查看周／日日期栏 | 星期 + 日期下方有农历小字；节气日（如 10 月 23 日霜降）显示节气名 |

| 整点选区 | 点击 10:45 附近的空白时间格 | 第一次只选中 10:00–11:00，整个小时有明显蓝色高亮和描边，不会直接弹表单 |
| 拖动调时 | 选中 10:00–11:00 后，向下拖动选区底部的粗线；再拖动顶部粗线 | 时段按 15 分钟扩展／收缩，提示条实时更新；拖到 12:00 和 10:30 后点「新建日程」，表单填入 10:30–12:00 |
| 两步新建 | 点击空白时间或拖选范围，再点击高亮区域或「新建日程」 | 第一步只选中，第二步打开表单并填入准确时段；手机轻触也适用 |
| 数字时间 | 手机上新建日程，在开始时间输入 `0930`，再点结束时间 | 输入框保持数字键盘，不弹出时钟表盘；失焦后自动变成 `09:30` |
| 类型标签 | 新建日程，查看「任务类型」 | 没有下拉菜单，也没有课程／科研等预设；显示「未分类」、自己创建的类型标签和「＋ 新建类型」 |
| 内联新建类型 | 点「＋ 新建类型」，输入名称、选主题色、点添加 | 新标签立即出现并被选中；保存后日程左侧色条使用该颜色；设置页同步出现该类型 |
| 编辑响应 | 反复打开／关闭编辑器、设置、详情 | 打开抽屉后先显示完整表单，再聚焦标题并弹出输入法；日历不闪烁、不重新滚动；保存／删除按钮始终固定在底部 |
| 更多菜单 | 点右上角竖排三点 | 菜单含时间轴 −／＋／重置、侧栏、待办清单、设置、深色模式、账号与退出登录，底部显示版本号 |
| 时间缩放 | 周／日中先滚动到下午，再用菜单放大、Ctrl+滚轮或双指缩放 | 保持正在看的时间位置；缩放比例记在本机，切视图和刷新后保持 |
| 视图切换 | 点年→月→周→日→日程，或点「回到今天」 | 视图按层级左右滑动；减少动态效果时没有滑动；「今」悬浮按钮与顶部今天图标功能一致 |
| 待办清单（桌面） | 查看左侧栏迷你月历下方；输入事项并回车 | 待办立即出现；可勾选、删除；列表上方显示未完成数量，拖动手柄可拖到日历 |

| 删除撤销 | 删除测试日程后点底部“撤销” | 原日程及时间、类型、备注恢复 |
| 连续撤销 | 连续修改同一日程两次，再撤销两次 | 依次恢复上一次和最初内容 |
| 拖拽／时长 | 桌面拖动日程，或拖动底边改变时长 | 保存后可点撤销，也可按 Ctrl+Z 恢复 |
| 长短标题 | 创建长标题的一小时日程，再创建 15 分钟日程 | 长标题最多三行；短日程自动隐藏时间行、优先标题；窄列只显示开始时间；悬停显示完整时间、类型、备注 |
| 深色模式 | 更多操作 → 深色模式 | 顶栏、网格、编辑器、菜单、悬浮按钮均为深色；切换后刷新保持 |
| 草稿已移除 | 查看顶栏、更多菜单和编辑器 | 没有任何「日程草稿」入口或保存草稿按钮；关闭未保存表单只能放弃或继续编辑 |

撤销保留本次日历页面的最近 20 步，刷新／退出后清除；输入框中的 Ctrl+Z 保留文字编辑行为。提醒设置按账号保存在当前设备，不跨设备同步，清除应用数据也会清除它们。浏览器、Windows WebView 和 Android 的本机数据相互独立。真实账号的类型、日程与待办保存到 Supabase；演示模式保存在本机。日程草稿功能已移除，旧版本留在本机的草稿不再显示或恢复。

快捷键：`Ctrl+Enter` 保存当前表单，`Esc` 关闭弹层，`Ctrl+Z` 撤销日历操作，`Ctrl+滚轮` 缩放时间轴，`← / →` 翻页，`T` 回到今天。

## 三、Windows 开机启动与提醒

1. 安装 0.5.0 后打开 **更多操作 → 设置 → 桌面功能**。网页会显示安装桌面版的提示。
2. 勾选“登录 Windows 后自动启动到托盘”；可以取消。下次登录 Windows 后，程序在托盘运行，点托盘图标打开窗口。
3. 点击“测试通知”，确认 Windows 通知中心能够收到通知；首次使用会申请系统权限。
4. 创建一条三分钟后开始的日程，勾选「提醒此日程」并设为「开始时」；再创建一条未勾选的日程作对照。点击窗口 X 隐藏到托盘，仅勾选的日程应提醒。
5. 同一个账号、同一个日程、同一次开始时间成功通知后会去重；拖动改变开始时间会产生新的提醒。

全天日程按当天 09:00 提醒。程序需登录并联网加载近期三天计划，前端每分钟刷新，原生线程约每十秒检查一次；已加载的计划在短暂断网时保留。提醒偏好仅保存在当前设备，不会自动同步到其他设备。

从托盘“退出”、关机或休眠期间不能准时提醒；恢复后仅补发尚未开始或开始不足一分钟的日程，避免大量过期通知。Windows 的“请勿打扰”和通知权限可能影响弹出效果，可查看通知中心。

Windows 系统通知需要安装后的应用注册信息，直接从开发目录运行时的行为与安装版不同，详见 [Tauri 通知文档](https://v2.tauri.app/plugin/notification/)。

## 四、自动化测试

在项目根目录：

```powershell
npm run typecheck
npm run lint
npm run test
```

单元测试覆盖表单校验、日期时间转换、关闭选择、撤销与版本冲突、数字时间输入、逐条提醒与全天规则、演示后端（含待办 CRUD 与 `task_id`）、农历/节气、自动更新流程等。

浏览器测试需要先启动演示服务器（不会连接 `.env.local`）：

```powershell
# 终端 1
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
npm run dev:demo -- --port 5173

# 终端 2
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
$env:E2E_BASE_URL='http://localhost:5173'
npm run test:e2e
```

浏览器测试覆盖桌面 Chrome 与手机尺寸 Chrome，包含实际鼠标拖动、底边拉伸及 Chrome 触屏事件（含左右滑动切视图、双指缩放）。演示数据位于测试浏览器独立环境，不改正式账号日程。缺少测试账号时真实登录用例跳过；桌面专属鼠标测试和手机专属触屏测试只在对应项目执行。

本版验证记录见 [开发进度](DEVELOPMENT_PLAN.md) 的 v0.5.0 段落。浏览器交互覆盖：大标题与视图标签、日期浮层、移动端滑动、窄时间列、农历日期栏、类型标签与内联新建、类型主题色同步、整点选区与上下粗线拖动、数字时间输入、待办拖入时间表、待办日程两步编辑与移回、草稿移除、撤销、连续拖动版本及减少动态效果。

测试范围：浏览器自动化不验证 Windows 启动注册项或系统通知；原生检查确认了调用和后台线程，系统通知弹出效果及 Android 真机手势仍需按上述步骤验收。真实云端同步及数据库 RLS 仍需独立测试账号与数据库验证。

已知开发日志：FullCalendar 尺寸重排时偶尔输出 `ResizeObserver loop completed with undelivered notifications`；当前交互回归通过，该日志没有通过隐藏错误的方式屏蔽。
