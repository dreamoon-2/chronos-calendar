# 0.2.0 功能体验与测试指南

## 一、打开正确的版本

**Windows 日常使用**：从系统托盘退出旧版 Chronos，运行 `src-tauri/target/release/bundle/nsis/Chronos Calendar_0.2.0_x64-setup.exe` 安装，再启动。桌面顶栏应显示 `v0.2.0`。系统通知和开机启动使用安装版测试；直接运行构建目录中的 exe 适合查看界面。

**Android 手机体验**：安装本次生成的 `android/app/build/outputs/apk/release/app-release.apk`，系统版本为 0.2.0，界面顶栏同样显示 `v0.2.0`。沿用本项目原有签名，可更新原 release 版；若此前装的是不同签名的 debug 版，先备份本机草稿与演示数据，再处理签名冲突。桌面开机启动与 Windows 通知入口只在 Windows 版提供。

**网页开发体验**：在 PowerShell 进入项目根目录，再启动开发服务器：

```powershell
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
npm run dev
```

保持终端运行，打开输出中的地址，默认 `http://localhost:1420`。以后修改 `src/` 通常自动更新页面。

- `ENOENT ... package.json`：终端没有位于项目根目录，先运行上面的 `Set-Location`。
- `Port 1420 is already in use`：先打开 `http://localhost:1420`；已有服务器可能正在运行。需要独立网页预览时可运行 `npm run dev -- --port 5173`，并打开 `http://localhost:5173`。
- Tauri 桌面开发固定使用 1420，需要先在占用该端口的开发终端按 Ctrl+C，再运行 `npm run desktop:dev`。
- 源码与已经打包的 exe／APK 分开更新。开发网页更新不会改变旧安装包。

## 二、手工体验清单

建议先用测试日程，避免误改自己的正式安排。

| 功能 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 简洁新建 | 点击空白时间格 | 首先显示标题、时间、类型；备注与跨天结束日期收在“更多选项” |
| 草稿 | 输入标题与备注，关闭表单，刷新页面再点添加 | 恢复上次输入，显示草稿提示；可主动丢弃 |
| 防误关闭 | 编辑时点击弹窗外 | 编辑器保持打开；关闭按钮、Esc 和手机返回键用于主动关闭 |
| 保存失败 | 对测试账号断网后尝试保存 | 显示错误，输入与编辑器保留；恢复网络后可重试。本机演示数据不依赖网络，因此用自动化用例验证失败分支 |
| 删除撤销 | 删除测试日程后点底部“撤销” | 原日程及时间、类型、备注恢复 |
| 连续撤销 | 连续修改同一日程两次，再撤销两次 | 依次恢复上一次和最初内容 |
| 拖拽／时长 | 桌面拖动日程，或拖动底边改变时长 | 保存后可点撤销，也可按 Ctrl+Z 恢复 |
| 长短标题 | 创建长标题的一小时日程，再创建 15 分钟日程 | 长标题最多两行；短日程优先标题；悬停显示完整时间、类型、备注 |
| 时间缩放 | 周／日中滚动到下午，再调整缩放 | 保持顶部正在看的时间；Ctrl+滚轮保持鼠标位置对应的时间，手机双指保持手势中心时间 |
| 月历缩放 | 周→月→日切换，再调整缩放 | 控件始终保留；月历行高随比例调整，放大后可以滚动 |
| 日期与样式 | 切换周／日，切换深浅色 | 星期下显示具体月／日，今天为蓝色强调，网格与卡片颜色协调 |

撤销保留本次日历页面的最近 20 步，刷新／退出后清除；输入框中的 Ctrl+Z 保留文字编辑行为。草稿按账号和日程隔离，仅保存在本机；清除浏览器数据也会清除草稿。若草稿基于旧版本日程，会禁止覆盖新版本，先复制需要的内容、丢弃草稿，再编辑最新日程。

快捷键：`Ctrl+Enter` 保存当前表单，`Esc` 关闭弹层，`Ctrl+Z` 撤销日历操作，`Ctrl+滚轮` 缩放时间轴。

## 三、Windows 开机启动与提醒

1. 安装 0.2.0 后打开 **设置 → 桌面功能**。网页会显示安装桌面版的提示。
2. 勾选“登录 Windows 后自动启动到托盘”；可以取消。下次登录 Windows 后，程序在托盘运行，点托盘图标打开窗口。
3. 勾选“日程开始前发送系统提醒”，选择提前量，点击“测试通知”，确认 Windows 通知中心能够收到通知。
4. 创建一条三分钟后开始的日程，将提醒时间设为“开始时”，点击窗口 X 隐藏到托盘，等待通知。
5. 同一个账号、同一个日程、同一次开始时间成功通知后会去重；拖动改变开始时间会产生新的提醒。

全天日程按当天 09:00 提醒。程序需登录并联网加载近期三天计划，前端每分钟刷新，原生线程约每十秒检查一次；已加载的计划在短暂断网时保留。提醒偏好仅保存在当前设备，不会自动同步到其他设备。

从托盘“退出”、关机或休眠期间不能准时提醒；恢复后仅补发尚未开始或开始不足一分钟的日程，避免大量过期通知。Windows 的“请勿打扰”和通知权限可能影响弹出效果，可查看通知中心。

Windows 系统通知需要安装后的应用注册信息，直接从开发目录运行时的行为与安装版不同，详见 [Tauri 通知文档](https://v2.tauri.app/plugin/notification/)。

## 四、自动化测试

在项目根目录：

```powershell
npm run typecheck
npm run lint
npm run test
```

单元测试覆盖保存失败、草稿恢复、旧版本保护、删除恢复与连续撤销、时间转换、提醒提前量和全天规则等。

浏览器测试需要先启动服务器。希望独立验证演示数据而不改 `.env.local` 时，在一个新终端执行：

```powershell
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
$env:VITE_SUPABASE_URL=' '
$env:VITE_SUPABASE_PUBLISHABLE_KEY=' '
npm run dev -- --port 5173
```

另一个终端运行：

```powershell
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
$env:E2E_BASE_URL='http://localhost:5173'
npm run test:e2e
```

浏览器测试覆盖桌面 Chrome 与手机尺寸 Chrome，包含实际鼠标拖动、底边拉伸及 Chrome 触屏事件。演示数据位于测试浏览器独立环境，不改正式账号日程。缺少测试账号时真实登录用例跳过；桌面专属鼠标测试和手机专属触屏测试只在对应项目执行。

本次验证：32 项单元测试、21 项浏览器交互测试通过，另 5 项按平台或测试账号条件跳过。Windows release 与 NSIS 打包、Android release 打包通过，APK 签名验证通过。Windows 原生运行补充检查了开机启动开关及恢复、通知权限、测试通知调用、后台提醒发送与去重；开机启动测试后恢复为关闭。

测试范围：浏览器自动化不验证 Windows 启动注册项或系统通知；原生检查确认了调用和后台线程，系统通知弹出效果及 Android 真机手势仍需按上述步骤验收。真实云端同步及数据库 RLS 仍需独立测试账号与数据库验证。
