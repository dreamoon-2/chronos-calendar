# 0.4.0 功能体验与测试指南

正式安装包见 [v0.4.0 Release](https://github.com/dreamoon-2/chronos-calendar/releases/tag/v0.4.0)，包含 Windows 安装包和 Android APK。也可按下方路径使用本机构建产物。

## 一、打开正确的版本

**Windows 日常使用**：从系统托盘退出旧版 Chronos，运行 `src-tauri/target/release/bundle/nsis/Chronos Calendar_0.4.0_x64-setup.exe` 安装，再启动。桌面顶栏应显示 `v0.4.0`。系统通知和开机启动使用安装版测试；直接运行构建目录中的 exe 适合查看界面。

**Android 手机体验**：安装本次生成的 `release/Chronos-Calendar_0.4.0_android.apk`，系统版本为 0.4.0（versionCode 5），界面顶栏同样显示 `v0.4.0`。沿用本项目原有签名，可更新原 release 版。桌面开机启动与 Windows 通知入口只在 Windows 版提供。

**云端账号升级**：已有 0.3.x 数据库需先执行 `supabase/migrations/202610190001_tasks.sql` 和 `202610200001_task_event_link.sql`，待办才能跨端同步并支持拖回；已执行过待办迁移的 0.4.0 数据库只需补执行后者。未执行时日程功能不受影响，待办面板会提示「待办表尚未创建」，执行迁移后点「重试」即可。

**网页开发体验**：在 PowerShell 进入项目根目录，再启动开发服务器：

```powershell
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
npm run dev
```

保持终端运行，打开输出中的地址，默认 `http://localhost:1420`。以后修改 `src/` 通常自动更新页面。

- `ENOENT ... package.json`：终端没有位于项目根目录，先运行上面的 `Set-Location`。
- `Port 1420 is already in use`：先打开 `http://localhost:1420`；已有服务器可能正在运行。需要独立网页预览时可运行 `npm run dev -- --port 5173`，并打开 `http://localhost:5173`。
- 启动新 exe 后仍显示旧版本：托盘里可能还有旧进程，Tauri 单实例会聚焦旧窗口。从托盘菜单「退出」旧程序后重新启动新 exe，顶栏版本号应更新。
- Tauri 桌面开发固定使用 1420，需要先在占用该端口的开发终端按 Ctrl+C，再运行 `npm run desktop:dev`。
- 源码与已经打包的 exe／APK 分开更新。开发网页更新不会改变旧安装包。

## 二、手工体验清单

建议先用测试日程，避免误改自己的正式安排。

| 功能 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 整点选区 | 点击 10:45 附近的空白时间格 | 第一次只选中 10:00–11:00，整个小时有明显蓝色高亮和描边，不会直接弹表单 |
| 拖动调时 | 选中 10:00–11:00 后，向下拖动选区底部的粗线；再向下拖动顶部粗线 | 时段按 15 分钟扩展／收缩，提示条实时更新；拖到 12:00 和 10:30 后点「新建日程」，表单填入 10:30–12:00 |
| 两步新建 | 点击空白时间或拖选范围，再点击高亮区域或「新建日程」 | 第一步只选中，第二步打开表单并填入准确时段；手机轻触也适用 |
| 待办清单 | 桌面侧栏或手机「待办」抽屉输入事项并回车；勾选、删除 | 待办立即出现在列表中；已完成项折叠在「已完成」下，可展开恢复或删除 |
| 拖入时间表 | 桌面按住待办拖到周／日时间格；手机长按待办后拖到上方时间格 | 松手后生成 1 小时日程，待办自动移入已完成；拖到月／年日期格生成全天日程；日程卡片显示「待办」标记 |
| 待办日程两步操作 | 点击待办生成的日程，长按或拖动；再次点击 | 第一次点击只选中并显示描边，可拖动／拉伸；再次点击进入编辑页 |
| 移回待办 | 在编辑器点「移回待办清单」；桌面也可把日程拖回左侧待办栏 | 日程消失，待办恢复为未完成并回到清单；只显示一条「已移回待办清单」提示，不保留旧撤销条 |
| 数字时间 | 手机上新建日程，在开始时间输入 `0930`，再点结束时间 | 输入框保持数字键盘，不弹出时钟表盘；失焦后自动变成 `09:30` |
| 年月周日 | 按年→月→周→日切换，年视图滚动查看月份；再点上／下一段 | 视图按层级左右滑动，日期翻页按方向滑动；不再淡入淡出；减少动态效果时没有滑动 |
| 选区取消 | 选中后按 Esc、点「取消」，或导航、切换视图 | 旧选区清除，不会误创建；再次点击空白重新选择 |
| 简洁新建 | 功能栏点添加，或确认选区 | 显示标题、时间、类型和本条提醒；备注与跨天结束日期收在“更多选项” |
| 手动草稿 | 输入标题与备注，点保存草稿后关闭，再刷新、新建 | 新建表单为空；在「日程草稿」中选择「修改并填入」可继续，保存为日程后移除对应草稿 |
| 关闭选择 | 输入后点关闭、Esc 或手机返回键 | 自行选择保存草稿并关闭、不保存并关闭、继续编辑；未选择保存就不会新增草稿 |
| 独立提醒 | 创建两条日程，只给其中一条勾选提醒；编辑、刷新再检查 | 提醒仅用于选中日程，开始时或提前量分别保存；新建默认关闭 |
| 防误关闭 | 编辑时点击弹窗外 | 编辑器保持打开；关闭按钮、Esc 和手机返回键用于主动关闭 |
| 保存失败 | 对测试账号断网后尝试保存 | 显示错误，输入与编辑器保留；恢复网络后可重试。本机演示数据不依赖网络，因此用自动化用例验证失败分支 |
| 删除撤销 | 删除测试日程后点底部“撤销” | 原日程及时间、类型、备注恢复 |
| 连续撤销 | 连续修改同一日程两次，再撤销两次 | 依次恢复上一次和最初内容 |
| 拖拽／时长 | 桌面拖动日程，或拖动底边改变时长 | 保存后可点撤销，也可按 Ctrl+Z 恢复 |
| 长短标题 | 创建长标题的一小时日程，再创建 15 分钟日程 | 长标题最多两行；短日程优先标题；悬停显示完整时间、类型、备注 |
| 时间缩放 | 周／日中滚动到下午，再调整缩放 | 保持顶部正在看的时间；Ctrl+滚轮保持鼠标位置对应的时间，手机双指保持手势中心时间 |
| 月历缩放 | 周→月→日切换，再调整缩放 | 控件始终保留；月历行高随比例调整，放大后可以滚动 |
| 日期与样式 | 切换周／日，切换深浅色 | 星期下显示具体月／日，今天为蓝色强调，网格与卡片颜色协调 |

撤销保留本次日历页面的最近 20 步，刷新／退出后清除；输入框中的 Ctrl+Z 保留文字编辑行为。草稿与提醒设置按账号保存在当前设备，不跨设备同步，清除应用数据也会清除它们。旧版自动草稿仍可在草稿列表中手动选择，填入后创建新日程，不覆盖原日程。浏览器、Windows WebView 和 Android 的本机数据相互独立。待办在真实账号下保存到 Supabase `tasks` 表；演示模式保存在本机。

快捷键：`Ctrl+Enter` 保存当前表单，`Esc` 关闭弹层，`Ctrl+Z` 撤销日历操作，`Ctrl+滚轮` 缩放时间轴。

## 三、Windows 开机启动与提醒

1. 安装 0.4.0 后打开 **设置 → 桌面功能**。网页会显示安装桌面版的提示。
2. 勾选“登录 Windows 后自动启动到托盘”；可以取消。下次登录 Windows 后，程序在托盘运行，点托盘图标打开窗口。
3. 点击“测试通知”，确认 Windows 通知中心能够收到通知；首次使用会申请系统权限。
4. 创建一条三分钟后开始的日程，勾选「提醒此日程」并设为「开始时」；再创建一条未勾选的日程作对照。点击窗口 X 隐藏到托盘，仅勾选的日程应提醒。
5. 同一个账号、同一个日程、同一次开始时间成功通知后会去重；拖动改变开始时间会产生新的提醒。

全天日程按当天 09:00 提醒。程序需登录并联网加载近期三天计划，前端每分钟刷新，原生线程约每十秒检查一次；已加载的计划在短暂断网时保留。提醒偏好仅保存在当前设备，不会自动同步到其他设备。

从托盘“退出”、关机或休眠期间不能准时提醒；恢复后仅补发尚未开始或开始不足一分钟的日程，避免大量过期通知。Windows 的“请勿打扰”和通知权限可能影响弹出效果，可查看通知中心。

Windows 系统通知需要安装后的应用注册信息，直接从开发目录运行时的行为与安装版不同，详见 [Tauri 通知文档](https://v2.tauri.app/plugin/notification/)。

## 四、自动化测试

在项目根目录：

```powershell
npm run typecheck
npm run lint
npm run test
```

单元测试覆盖保存失败、主动保存草稿、关闭选择、旧草稿兼容与账号隔离、删除恢复与连续撤销、时间转换、数字时间输入、逐条提醒与全天规则、演示待办 CRUD 等。

浏览器测试需要先启动服务器。希望独立验证演示数据而不改 `.env.local` 时，在一个新终端执行：

```powershell
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
$env:VITE_SUPABASE_URL=' '
$env:VITE_SUPABASE_PUBLISHABLE_KEY=' '
npm run dev -- --port 5173
```

另一个终端运行：

```powershell
Set-Location -LiteralPath 'D:\Users\dreamoon\Documents\vibe coding\Schedule\chronos_calendar_blueprint'
$env:E2E_BASE_URL='http://localhost:5173'
npm run test:e2e
```

浏览器测试覆盖桌面 Chrome 与手机尺寸 Chrome，包含实际鼠标拖动、底边拉伸及 Chrome 触屏事件。演示数据位于测试浏览器独立环境，不改正式账号日程。缺少测试账号时真实登录用例跳过；桌面专属鼠标测试和手机专属触屏测试只在对应项目执行。

本版验证记录见 [开发进度](DEVELOPMENT_PLAN.md) 的 v0.4.0 段落。浏览器交互包含鼠标与真实轻触的整点选区、明显高亮、选区粗线拖动调时、桌面／移动端待办拖拽、数字时间输入、视图左右滑动及减少动态效果偏好。

测试范围：浏览器自动化不验证 Windows 启动注册项或系统通知；原生检查确认了调用和后台线程，系统通知弹出效果及 Android 真机手势仍需按上述步骤验收。真实云端同步及数据库 RLS 仍需独立测试账号与数据库验证。

已知开发日志：FullCalendar 尺寸重排时偶尔输出 `ResizeObserver loop completed with undelivered notifications`；当前交互回归通过，该日志没有通过隐藏错误的方式屏蔽。
